Create

Build a message or mosaic theme as JSON (and optional JS), then import it from the popup. Imported themes stay in Chrome storage and show up in the dropdowns with (imported) after the name.

Start with a test pack

Download a JSON-only pack first — no engine file — so it is the safest import to try. After import, pick it in the popup. Size, color, and message motion appear under that dropdown.

Download message-stamp.json Download mosaic-framed.json

message-stamp.json is a postage-stamp card with Ink, Paper, Background, and Motion. mosaic-framed.json is a Polaroid-like scatter with Photo size and Frame color.

Import from the popup

  1. Reload the unpacked extension (or reinstall extension.zip). On first install, complete the Finish setup tab Chrome opens.
  2. If the pack includes a *-engine.js file: open extension details → turn on Allow User Scripts (Chrome 138+), or keep Developer mode on for older Chrome. The popup shows a red Finish setup banner until this is done. JSON-only packs can skip this.
  3. Open the extension popup.
  4. Under Imported themes, click Import packs….
  5. Select one or many theme .json files, plus each pack’s *-engine.js if it has one, plus optional custom font files (.woff2 / .woff / .ttf / .otf). Matching is automatic: engines by engine / filename; fonts by each JSON fontFile / fontFaces[].fontFile. A pack can use several custom fonts plus Google Fonts; shared files are stored once.
  6. Select the imported theme in Message dynamic template or Mosaic dynamic template.
  7. Under Stage, the default is Match Vixi (Vixi’s canvas). Other ratios letterbox in black. Match the window fills the browser. Under Mosaic and Message, turn Show background / QR / logo on only for that kind.
  8. Open a Vixi output page and hard-refresh it after enabling User Scripts or importing an engine.

A pack that includes JS runs on matching output pages only after Allow User Scripts is on. Only import engines you wrote or trust. The popup warns the first time. Re-importing the same theme id (or the same engine / font file) replaces the previous copy. Remove an imported theme from the same section — if it was selected, the dropdown returns to Off.

To check a pack before Chrome, open preview and use Import packs… the same way (JSON, plus *-engine.js and font files if the pack needs them). The preview compiles engines in the page, so Allow User Scripts is not required there. Open viewer hides the dock and shows only the stage. Imported packs stay in this browser until you click Remove. Importing the same name again replaces that pack and does not replace a built-in theme. Output still needs the extension, and engine packs on output still need Allow User Scripts.

Why engine packs need Allow User Scripts

Chrome blocks running imported JavaScript inside the extension’s normal content scripts (page CSP / MV3). The extension registers your engine with Chrome’s user scripts API instead. That API stays off until you opt in on the extension details page. Without the opt-in, mosaic/message mounts fail and the stage stays black. Built-in themes shipped in the extension do not need this step.

Custom fonts

Google Fonts and imported files can both be used on the same pack. For Google Fonts, set "fonts" to a CSS URL (several families in one URL is fine) or an array of URLs, then use those families in CSS.

For one or more non-Google faces, put the files next to your packs and prefer fontFaces:

{
  "fonts": "https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap",
  "fontFaces": [
    { "fontFile": "BrandDisplay.woff2", "fontFamily": "Brand Display" },
    { "fontFile": "BrandBody.woff2", "fontFamily": "Brand Body" }
  ]
}

Singular fontFile / fontFamily still works for one face. Select every named font with the JSON (and engine, if any) in Import packs…. Prefer .woff2 (about 2 MB max each). In CSS: font-family: "Brand Display", Inter, sans-serif;

Extra Vixi questions

Vixi’s first on-screen text is message, the second is name, and everything after that is question1, question2, … in DOM order (V2 skips empty tiles first). Bind extras with data-field="question1" or data-question="1". Existing name/message themes do not need to change.

Standard JSON has no // comments. Put labels for those extras in a top-level notes object — the importer ignores it. Class Survey is the example. Full rules: Extra Vixi questions in the spec.

Live popup settings

Imported packs use the same live-settings pipeline as bundled themes. Declare controls under settings in your JSON, then wire CSS to var(--primary), var(--secondary), var(--background), var(--frame), var(--scale), [data-motion], and [data-photo-style] on the scoped theme root — not hardcoded hex on layers that should recolor. For a solid backdrop, use the background setting (see message-stamp.json). Import copies font files with the pack, not images — see Imported packs vs bundled image backdrops. JSON-only packs need no extra code; engines should call BGMessageThemes.applyVars from applySettings. See Live settings for imported themes in the spec and clone message-stamp.json or mosaic-framed.json.

QR, logo, and layout variants

Put data-qr and data-logo on the boxes that should receive Vixi’s marks when those toggles are on. Style them for exact size and position. Omit them to use the default corners, or leave the toggles off to hide chrome entirely.

The theme root gets dyn-show-qr, dyn-show-logo, and dyn-show-bg when those checkboxes are on. Use those classes in CSS for four layouts: neither, logo only, QR only, both. Prefer reflowing content away from the chrome rail instead of clipping photos with a hard mid-stage edge. Full examples are in themes/SPEC.md.

Hand this to an AI

Attach themes/SPEC.md and the closest example, then paste:

You are writing a Dynamic Backgrounds theme pack. Read themes/SPEC.md and clone the closest example. Follow the spec exactly. Output valid JSON and, if the brief needs JS, a classic-script engine that calls BGThemeEngines.define. Do not invent fields. Do not use reserved ids. Scope all CSS. If you add an engine, id in define() must match JSON "engine". Prefer data-qr / data-logo slots and dyn-show-qr / dyn-show-logo layout variants when the brief mentions QR or logo. Suggested names: message-<name>.json / message-<name>-engine.js or mosaic-<name>.json / mosaic-<name>-engine.js (optional).

Then describe the look. The spec lists every field, clamp, reserved id, reject rule, and engine hook.

Limits: up to 24 imported themes. CSS max 100 KB, HTML max 50 KB, engine JS max ~200 KB. Importing the same id again replaces the previous pack.
